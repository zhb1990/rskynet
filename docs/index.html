rskynet

用 Rust 复刻 skynet 的 Actor 内核。不需要 Lua——skynet 用协程解决的问题，Rust 的 async / Future 原样解决，还多了编译期类型检查。

项目定位

rskynet 是一个把 skynet 的 Actor 调度内核搬到 Rust 的项目。它保留了 skynet 的调度语义，但把协程换成 Rust 的 Future：服务挂起时阻塞的只是当前任务，服务本身照常处理其他消息。内置的日志、定时器、信号、引导、网络、TLS、HTTP 与 cluster 都不是内核的一部分，而是普通服务，与业务服务走同一条接入路径。

skynet 的做法rskynet 的做法
服务即 Actor：独立地址、独立邮箱、消息通信实现 Service trait，状态放进 SvcCell，服务内单线程
两级消息队列：每服务邮箱 + 全局运行队列Mailbox + 每 worker 一条 BWoS 队列 + injector，两级队列都不加锁
call 分配 session 并挂起协程，回包带同一 session 唤醒session → Waker，call 就是一句 .await

调度模型有一处推广：服务的「可运行」条件从「邮箱非空」推广为「邮箱非空或存在就绪任务」。定时器回包、RPC 回包、外部线程唤醒因此走同一条路径，一个邮箱状态机同时管住消息与 Future 唤醒。

总体架构

使用方只依赖门面 crate rskynet。门面按 feature 把内置服务 crate 拼起来，向内核注入 Timer 实现、注册服务类型，再调用 rskynet::start(config, registry)。内核不碰 epoll、文件 IO 与系统时钟，因此可以跨平台运行。

内核对象模型

服务视角

Service 的 init 对应 skynet 的启动协程，dispatch 对应消息处理函数；Exclusive 只多 idle 与 interrupt 两个钩子。应用代码通常用 #[service] / #[exclusive] 生成底层 BoxFuture 包装。

内核运行时

Node 是节点的私有内核对象，外部只能拿到 NodeRef；ServiceContext 等价于 C 版 skynet_context；邮箱、session 表与任务集都只由「当前持有该服务的线程」访问。

为什么服务状态可以不加锁

调度器保证同一个服务任意时刻只被一条线程执行。该不变量由邮箱状态机的 Queued → Running 这一次取出维持；BWoS 保证每个槽位只会被取走一次，被偷走只是换一个 worker。独占线程服务更是从头到尾只有那一条线程。SvcCell<T> 本质是 RefCell，只额外声明 Sync，让 Arc<MyService> 满足 Send。跨 await 持有 Mutex 会死锁，而 SvcCell 在借用冲突时 panic，能第一时间暴露 bug。

调度模型：无锁邮箱与工作窃取

C 版邮箱是「一把锁 + 环形缓冲 + in_global 布尔量」。rskynet 换成两条无锁 SegQueue 加四态原子状态机。「队列已空」与「放生服务」必须原子绑定，否则会丢活，因此状态机不是可选项。

三条纪律：投递方先压队列、再改状态；入队方先改状态、再入队；销毁流程最后一步才放生，且确认清理期间没有新活才成功。

运行队列换成每 worker 一条 BWoS 块式工作窃取队列。owner 在自己的队列上 push/pop 不需要锁；本地队列是 LIFO；空闲 worker 从别人队列头部窃取最老的服务。非 worker 线程投递、本地队列溢出以及「有人在找活」时走 injector。

worker 主循环

每干满 64 件活（消息与就绪任务各算一件）才读一次 pending：确实有别人在等才让渡；没人等就重新计数。独占服务不参与让渡。

投递与唤醒

worker 侧先登记 idle 位再扫队列；投递侧先入队再读位图，两侧以 SeqCst fence 配对。唤醒者取位图最低位，并用 searching 计数与 handoff 槽省掉无谓唤醒。

邮箱状态与运行队列的所有写入顺序都经过单独推演：先压队列后改状态保证 Notified 复位重扫必有收获；先改状态后入队保证服务不会「标记在队列里、实际谁也没拿着」。

消息、session 与 RPC

一条消息包含 source、session、mtype 与 payload。RESPONSE / ERROR 且带 session 时，内核直接唤醒等待任务，不进入 dispatch；其他消息为服务开一个新任务，等价于 skynet 新建一个协程。

消息路径

  • send / post：投递后不等待。
  • call / request：分配正数 session，发消息后返回 Call Future；首次 poll 时把 Waker 登记进 session 表。
  • 回包到达：SessionTable::complete 把结果存入 Done 槽位，再释放借用并 waker.wake()。
  • 等待方取消：留下 Abandoned 墓碑，迟到回包直接丢弃。

最小服务

use rskynet::{Config, ConfigExt, Ctx, Message, Registry, Result};

struct Echo;

#[rskynet::service]
impl Echo {
    async fn init(&self, ctx: Ctx) -> Result<()> {
        ctx.register_name("echo");
        Ok(())
    }

    async fn dispatch(&self, ctx: Ctx, mut msg: Message) {
        let payload = msg.take_payload();
        let _ = ctx.reply(&msg, payload);
    }
}

fn main() -> Result<()> {
    let registry = Registry::new().with("echo", || Echo);
    let config = Config::default().with_bootstrap(["echo"]);
    rskynet::start(config, registry)
}

这段代码读起来是同步的，实际上挂起的只是当前任务：

// 读起来是同步的，实际上挂起的只是当前任务

时间来源与分层时间轮

内核没有时间轮，只有一个必须注入的 Timer trait。rskynet-timer 提供配合的两半：WheelTimer 负责记账（注入内核，谁都可以压事件），TimerService 是独占线程服务，负责推刻度并把到期事件派发成 RESPONSE 消息。

结构参数覆盖范围
近期轮 near256 格 × 10ms2.56 秒
第 1 层64 格约 163.84 秒
第 2 层64 格约 10485 秒
第 3 / 4 层64 格逐级放大，添加与到期 O(1)

ctx.sleep 不经过定时器服务邮箱：它把事件压进 WheelTimer 的无锁队列，由定时器服务每 tick 插轮；到期时刻在入队前按绝对时间算好，所以晚一个 tick 插入也不会让定时器变长。

启动、引导与优雅关停

标准入口按 日志 → 信号 → 定时器 → 可选基础设施 → 引导 顺序拉起，每一步等待完整 init。可选服务按依赖稳定排序为 net → tls → http-client → cluster。日志最先，保证后面的错误有人记录；定时器排在引导前，引导期间刻度就在走。

ctx.launch(...).await 以目标服务 init Future 完整返回 Ok(()) 为成功。bootstrap 严格逐项等待；常驻循环与长期握手应放进 ctx.spawn。

关停顺序

  • worker 收工，主线程 drain() 排空 injector。
  • retire_all() 送走普通服务，并给在途请求回错误。
  • 独占线程被摘除后自行 drain 邮箱再销毁，最后 join。
  • 保留服务分两批：先送走定时器等，logger 最后走。
启动阶段服务数短暂归零不会提前关停；booted 标记由引导完成时置位，之后最后一个服务退出才触发 quit()。

独占一条线程的服务

日志、定时器与网络层在 C 版是专用线程，在 rskynet 是「独占线程的服务」。它们不进入运行队列，邮箱有活时由投递方 unpark 专属线程并调用 interrupt 钩子；空闲时由服务自己的 idle 决定怎么睡。

共享服务独占服务
执行者运行队列上的某个 worker，可能被窃取自己的专属线程，从不进运行队列
空闲时找别的服务，找不到挂起调 idle 钩子
有活投进入运行队列，按空闲位图定向唤醒unpark + interrupt
适用业务服务，一万个只是一万个邮箱阻塞在 epoll/mio 或按节拍醒来的活

interrupt 必须接得住早到的唤醒：std park 令牌与 mio Waker 满足，Condvar 不满足。

死循环检测、信号与崩溃报告

monitor 死循环检测

每个 worker 各有一份 monitor 进度，rskynet-monitor 线程每 5 秒扫描。同一次 Future poll 连续跨过两个检查点仍未返回，就记录来源与目标 handle 的疑似死循环日志。检测只告警，不强杀线程；node.take_endless(handle) 读取并清除一次性标记。

信号服务

Unix 的 SIGINT / SIGTERM 与 Windows Ctrl+C 默认调用 NodeRef::abort() 优雅关停。#[signal(SIGTERM)] 可注册同步回调，回调在信号服务独占线程上执行，不在 OS signal handler 中运行。

独立 crash helper

标准入口会自动启动同一可执行文件的隐藏 crash helper。panic 发元数据，原生崩溃只做崩溃安全的最小请求，符号化、文件 IO 全部在 helper 进程中完成。

网络、TLS、HTTP 与 WebSocket

NetService

网络层是独占线程服务：idle 是 poll.poll(events, None)，interrupt 敲 mio 的 Waker。业务服务的 net::listen / connect / send / close 是发命令消息，办完回包，调用方写成 await；socket 事件以 MsgType::SOCKET 投给属主。

域名解析另起阻塞线程，靠 ReplyToken 回话。连接建立后默认停在 PreAccept，等新属主调用 start，避免第一个字节投错服务。

TlsService

TLS 不接管 socket：它在网络层之上把 rustls 驱动成普通 actor。业务服务看到 TlsId 与明文 TlsEvent，底层密文仍由 NetService 收发。

HTTP / WebSocket

HttpClientService 是共享连接池客户端 actor；服务端没有全局 actor，业务服务持有 HttpServer，把 SocketEvent / TlsEvent 交给它解析。两侧都基于 ureq-proto 的 Sans-IO HTTP/1.1 状态机，支持 keep-alive、chunked、100-continue、流式 body 与背压。WebSocket 服务端内嵌在 HttpServer 中，升级时保留 HTTP 解析器尚未消费的首帧数据。

网络层最小示例

use rskynet::net::{self, SocketEvent};

#[rskynet::service]
impl EchoServer {
    async fn init(&self, ctx: Ctx) -> Result<()> {
        let id = net::listen(&ctx, "0.0.0.0:8888").await?;
        net::start(&ctx, id).await?; // 从此开始 accept
        Ok(())
    }

    #[msg(MsgType::SOCKET)]
    async fn on_socket(&self, ctx: Ctx, event: SocketEvent) {
        match event {
            SocketEvent::Accept { id, .. } => { let _ = net::start(&ctx, id).await; }
            SocketEvent::Data { id, data }  => { let _ = net::send(&ctx, id, data); }
            _ => {}
        }
    }
}

cluster：跨节点 Protobuf 通信

本地 actor 直接传 Payload::Boxed 对象；只有实现 ClusterMessage 的 Protobuf 类型进入网络路径。消息的 TYPE_ID 与入站 handler 由宏提交到链接期注册表，配置出现 [cluster] 时自动启动并注册 handler。

#[derive(Clone, PartialEq, prost::Message, rskynet::cluster::ClusterMessage)]
#[cluster(type_id = 1001)]
struct PingRequest {
    #[prost(uint64, tag = "1")]
    round: u64,
}

#[rskynet::cluster::handler("pong")]
async fn pong(
    remote: rskynet::cluster::RemoteContext,
    ping: PingRequest,
) -> Result<PongResponse, String> {
    let reply = remote.request("pong-worker", rskynet::Payload::of(ping)).await?;
    reply.downcast::<PongResponse>().map(|r| *r)
}

RemoteContext 提供带路由、TYPE_ID、来源节点与请求 ID 的日志，也可把工作转交给本地 actor；跨节点边界用 Protobuf，本地转交仍传对象，不重复序列化。

观测与 Dashboard

节点级观测统一走 NodeRef：node.stats() 返回服务总数与运行队列长度，node.services() 返回每个 service 的 kind、别名、生命周期、邮箱积压、活动 task、pending call、消息数与 CPU 微秒数。抓取过程不访问 SvcCell，不阻塞服务执行。

Dashboard 页面与 /api/v1/stats 直接嵌入可执行文件，部署时不需要额外静态资源。存在 [cluster] 时还会显示本节点 node_id。

宏、配置与 feature 工程化

过程宏

#[service] / #[exclusive] 生成 trait 实现；#[msg] 按协议号路由并通过 FromPayload 取参数，有返回值且发送方在等待时自动回包。

#[rskynet::service]
impl Calculator {
    async fn init(&self, ctx: Ctx) -> Result<()> {
        ctx.register_name("calculator");
        Ok(())
    }

    #[msg(MsgType::USER)]
    async fn add(&self, ask: Add) -> Sum { Sum(ask.0 + ask.1) }

    #[msg(default)]
    async fn other(&self, _ctx: Ctx, _msg: Message) {}
}

性能、边界与测试

压测读数

AMD64 Windows，22 逻辑核。加锁版与无锁版交替各跑五轮取中位数，单轮有约 ±10% 抖动。

场景加锁版无锁版
