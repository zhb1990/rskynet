Actor kernel / no Lua

同一服务，一条线程。

rskynet 用 Rust 复刻 skynet 的 Actor 内核。服务即 Actor，邮箱是无锁四态机，session 把 call 写成一句 .await。Lua 协程换成 Future 之后，语义一字不差，内核里一个服务都没有。

邮箱状态机

DWG-MQ-01
Idle

两条队列都空，服务不在运行队列里。

Queued

投递方 CAS 成功，由它负责把服务推进运行队列。

Running

唯一持有者。同一时刻不会有第二个 worker 执行它。

Notified

持有期间又来了新活。投递方不必再入队，消费方复位后重扫。

服务创建时落在 Queued，worker 取走后进入 Running。

C 版靠一把邮箱锁把「队列已空」和「放生服务」绑在一起。无锁化之后，这两件事必须用四个状态显式绑住，否则会丢活：消费方看见空队列，投递方看见仍在队列里于是不再入队，那条消息从此无人处理。

三条纪律：投递先压队列再改状态；入队先改状态再入队；销毁的最后一步才放生。

可运行条件从「邮箱非空」推广为「邮箱非空或有就绪任务」。定时器回包、RPC 回包、外部线程唤醒，走同一条路径，由这一个状态机同时管住消息与 Future。

层级怎么叠

使用方只依赖门面 crate rskynet。内核不碰 epoll、文件和系统时钟；日志、定时器、网络、TLS、HTTP、集群都是外面的普通服务。

一个服务里有什么

ServiceContext 是运行时的中心对象。调度器保证任意时刻只有一条线程执行它，所以内部容器可以是 SvcCell，不必上锁。

调度怎么跑

worker 从运行队列取一个服务，优先 poll 就绪任务，其次取消息。每 64 件活问一次有没有别人在等；有就让渡，没有就接着跑。

消息怎么走

同进程传对象走 Payload::Boxed，零拷贝。跨节点才走 Protobuf。应答类消息不进 dispatch，由内核按 session 唤醒任务。

各模块怎么工作

模块名刻意对齐 skynet-src，方便对照。C 版没有对应物的是 Exclusive、ext、Timer 抽象和 BWoS。
